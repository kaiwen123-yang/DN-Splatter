2. 在本地本项目工作区检查 Git 远端和未提交修改，获取上述仓库最新内容。已有 checkout 就接续，未存在时在合适的本地工作目录 clone；保留已有修改，不覆盖、不 reset --hard。先读 AGENTS.md、docs/07_local_bag_audit.md、configs/capture_bag_audit.json；docs/06_custom_data.md 作为后续接入背景。
3. 只读盘点本机 Python、已有 bag 读取器、CPU/RAM、可用磁盘。优先复用兼容工具；缺依赖时在本项目 .local 下新建轻量 venv/Conda 环境，记录精确版本。可按实际格式使用 rosbags/rosbags-image；无需为这次读取复制 AutoDL CUDA 环境，也不要求安装完整 ROS、Docker 或 WSL。不要改 base、全局包或其他项目环境。
4. 本机 GitHub 使用现有连接和凭据。AutoDL 官方学术加速仅适用于实际发生在 AutoDL 的 GitHub 操作，不把其代理写入本地全局配置。

## 2. 原包保护与可读性

原包只读。不上传原包到 Git/Git LFS/云端，不全量复制或解包，不原地 reindex/repair/convert，不修改、重命名或删除，不执行 rosbag play，不连接真实机器人。完整消息时间表、额外全分辨率图像等中间结果留在项目 .local 下。

记录实际路径、字节数、mtime、文件头/真实格式，并流式计算一次 SHA-256。扫描结束再次检查大小/mtime；若采集仍在写入或文件变化，标记不稳定及实际覆盖，不能称完整审计完成。不要把 .bag 扩展名当作标准 ROS1 格式的证明；辨别 ROS1/ROS2/MCAP 或厂商 SDK 录制及其消息定义。读取器缺少类型定义/解码能力不等于文件损坏；保存具体错误，继续完成仍可读取部分，不写入原文件修复。

## 3. 实际分析

实现或复用必要的可重复分析脚本，放入 scripts/ 跟踪目录。按实际数据逐步完成，不建立庞大通用框架，不用伪造样例代替真实文件验证。

- 列出全部话题/连接、消息类型、计数、起止时间、时长、频率和 frame_id；识别彩色、红外、原始/配准深度、CameraInfo、TF、位姿/里程计、IMU 等。通过消息内容、标定和编码判断角色，不能只看话题名称。说明元数据与实际扫描的覆盖及任何读取失败。
- 完整扫描选定相关话题的时间信息，图像内容按全时段抽样。分别保存记录时间和 header 时间；内部使用整数纳秒，JSON 中绝对纳秒写十进制字符串。记录重复、跳变、间隔分位数及最大缺口。某些 reader 按记录时间排序，不能据此证明原始写入顺序无倒序。CameraInfo/静态TF的零时间戳按语义处理。
- 分析所有合理 RGB/深度组合的时间关系，记录所选话题、时钟依据、符号偏差、p50/p95/p99/max、唯一配对覆盖与未匹配数。最近邻诊断与最终一对一配对区分；不能反复复用同一深度帧而不说明，也不能悄悄校正时钟。可比较多个毫秒阈值，阈值是诊断而不是通用合格线。
- 检查图像编码、尺寸、step、端序和实际解码方式；均匀抽取约24个时间位置，另加少量异常位置。报告清晰度、曝光、重复帧、主体静动态和视角变化，说明抽样范围与局限。光流/内容变化不直接证明相机存在足够的平移基线。
- 深度保留原始数值和dtype，检查有效/无效值定义、0/NaN/Inf/饱和、分位数和可用比例。记录深度单位的实际证据；未知 metres_per_unit=null，不能仅凭16UC1就断言毫米。识别Z深度/射线距离及compressedDepth编码，不把所有压缩深度当普通PNG解码。所有像素统计注明抽样覆盖。
- 保存相关CameraInfo完整K/D/R/P、分辨率、畸变模型、ROI、binning和变化情况；区分raw/rectified图像的标定。核实深度到RGB的外参和注册证据，相同尺寸、aligned话题名或resize都不能单独证明配准正确。
- 重建相关TF关系，区分静态外参和动态轨迹；检查位姿来源、方向、时间覆盖、单位、轴约定、四元数、跳变/重置和协方差语义。机器人机身/末端轨迹需外参才能变成相机轨迹；IMU、静态TF或点云的存在不等于逐帧相机位姿可用。
- 有真实相机轨迹时分析相对路径、平移/旋转范围、间断及视角覆盖；无位姿则明确缺失，不补身份矩阵。只有内参、深度单位/含义和位姿都具备证据时，才做最多5–10帧的稀疏反投影/重投影核对。不运行完整SfM/SLAM或全量重建。
- 用 confirmed/missing/unknown/not_applicable/failed 分项说明：可用RGB、多视角、静态内容、内参、逐帧相机位姿、尺度/坐标一致性、深度、单位、RGB-D配准和时间对应。给出多项缺失条件和依据，不用一个“ready=true”掩盖未知项。

## 4. 回传内容

遵守 configs/capture_bag_audit.json 的字段、命名和体积协议。运行目录使用真实开始时间和实测源SHA256前8位生成：

reports/capture-bag-audit/<run-id>/

至少包含：

- overview.md：中文结论，真实检查范围、发现、缺失条件、推荐接入路线及下一步；
- summary.json、topic_inventory.json、timing.json、sync.json；
- calibration.json、frame_graph.json、trajectory.json；
- image_quality.json、depth_quality.json、samples_metadata.json；
- artifact_manifest.json：相对路径、大小、SHA256和清单范围，不递归计算自身hash；
- previews/：全时段RGB/深度拼图、必要同步图和有证据时的相对轨迹/配准预览；
- samples/：存在相应流时提供3–5组代表性RGB与保留原数值的无损深度，优先3组早/中/晚。深度可用NPZ/NPY或适合的16位PNG，不只交彩色可视化。元数据包含原话题、时间、消息身份、编码/形状、标定关联、位姿来源及同步误差。单位未知如实保留，缺流或解码失败明确说明。

公开报告使用相对时间和归零轨迹，保留解释坐标关系所必需的信息；原始地理位置、无关话题载荷、设备序列号、凭据和完整环境变量不进仓库。图片预览缩放/裁剪必须注明，深度使用统一且明确的色标。

报告包目标不超过20MiB，发布上限50MiB。优先减少非必要预览和样例数量，不量化或篡改深度数值；极大分辨率时按协议保留有精确ROI映射的原数值样本并说明限制。原包及批量全量导出始终留本地。

保存分析脚本、必要的版本锁定/依赖记录和实际执行命令，方便再次审查。更新 reports/capture-bag-audit/latest.json 指向本次真实报告，记录 complete/partial/blocked 及原因；latest.json 与其指向的报告放在同一个提交中发布。不覆盖 reports/latest_status.json 或历史VR Room结果。
