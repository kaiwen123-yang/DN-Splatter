# capture-full 原始网格与导出链复核

复核日期：2026-11-20（北京时间）。输入固定为提交 `e26ae72a75997dcfd3a907aa26b6c5c0677597a5`。数值和来源文件哈希见 [mesh_findings.json](mesh_findings.json)。本次读取了已提交的 JSON、运行代码和代表图片；没有访问 AutoDL 上的完整 PLY，也没有重新执行导出或观看本地完整 MP4。下文明确区分执行端已测量的数值、当前实际观察到的画面和尚未执行的方法建议。

## 1. 结论：原始网格的局部失败已超出薄结构变粗

完整建图、训练、导出链已经执行结束，但当前原始 Poisson 还不能作为可信的场景几何资产。桌沿和椅腿局部中，模型深度仍能辨认目标形状，融合采样点云的投影也隐约保留轮廓；网格首交点深度却几乎整片落在色标近端，顶点色和面明暗显示相机前方的大片遮挡表面。柱面局部同样被粗大前景面遮挡，主体轮廓没有按模型深度保留下来。这不是只需再平滑一下桌沿的细节问题。[桌沿图][table]、[柱面图][pillar]、[椅腿图][chair]

这些画面与局部深度统计一致，支持“当前融合与曲面导出存在显著的前景伪面/遮挡问题”。但不能只看色标就给出精确的伪面距离；颜色在0.3–6m范围截色，需要原数组的有符号残差和近前方首交点计数进一步量化。全局外视图也能看到粗糙的大面积壳状表面和碎片，不能把网格面数多或主体连通当作质量足够。[全局图][global]

## 2. 三处局部的正确比较口径

以下数值来自原始 `mesh_validation.json`，参考为同次采集训练帧的有效传感器Z，不是独立几何真值。[网格核验][validation]

| 局部 / 主训练帧 | 参考像素 | 模型MAE | 融合点云匹配像素 / 覆盖 | 融合点云MAE | 网格MAE |
| --- | ---: | ---: | ---: | ---: | ---: |
| 桌沿 / 120 | 24,129 | 0.36251 m | 20,528 / 85.08% | 0.84641 m | 3.58941 m |
| 柱面 / 0 | 24,902 | 0.09705 m | 20,670 / 83.01% | 0.50835 m | 2.24188 m |
| 椅腿 / 240 | 24,695 | 0.17247 m | 15,711 / 63.62% | 0.68171 m | 3.32591 m |

模型和网格在这三个裁片都覆盖全部有效参考像素，因此两者的MAE是在相同支持上计算的，网格显著更差这一判断成立。当前模型也已有误差，尤其桌沿0.36m，不能认为模型几何已正确、全部问题只在Poisson。

**点云列不能直接解释成“同一深度值在随机采样时从0.36m误差变成0.85m误差”。** 代码把全部1,478个训练视角的融合采样点投影回当前裁片，再取每像素最近的正Z；它不只是当前视角原深度图的子样本。同时，点云只有部分参考像素有命中，支持集合与模型/网格不同。跨视角不一致、来自其他视角的浮点遮挡、像素量化和采样缺口都可能影响这一投影。[局部比较代码][code]

下一轮完整导出报告应同时给出：

- 每种结果在完整参考支持上的覆盖率、无命中数和各自有效支持指标。
- 模型、点云、网格均有效的共同像素交集上的配对指标，不能仅横排不同分母的均值。
- 网格首交点低于0.3m、以及比参考提前超过固定容差的比例；同时给出有符号误差分布，区分伪前景和表面后移。
- 融合点云每个投影获胜点来自哪个源视角；当前原始PCD可按每视角固定样点数和 `sampling.json` 顺序恢复来源块。新导出直接保存源帧ID与源像素索引。
- 当前视角自身样点反投影再投回原视角的坐标/Z一致性，与全部视角融合后的最近Z误差分开报告。该记录嵌入完整导出，不新增短训练或用户审阅阶段。

## 3. 已有源码不能支持“坐标轴写反了”的结论

固定历史实现的深度与法线链如下。[历史导出器][exporter]、[相机工具][camera]、[模型法线][model]

- 数据相机是OpenGL c2w，导出深度时右乘 `D=diag(1,-1,-1)` 得到OpenCV相机旋转，再将彩色光轴Z反投影到世界。
- 反投影像素使用 `u+0.5, v+0.5`；当前数据的Nerfstudio内参已经包含相应一次半像素转换。代码没有在这里重复增添另一米制尺度。
- 模型法线是相机OpenGL坐标表达；导出先对法线乘D，再用 `R_cv=R_gl D` 转回世界。两次D相消，得到 `R_gl n_gl`，数学上正确。
- 局部网格射线在相机坐标中为 `[(u+0.5-cx)/fx, (v+0.5-cy)/fy, 1]`，没有归一化为单位长度；因此 `t_hit` 对应相机Z，不是误把欧氏射线距离当Z。

这排除了当前可见代码中一个直接的轴翻转/射线距离误读解释，**不等同于证明全部输入位姿准确，或全部法线方向跨视角一致**。报告中的单位长度和有限性统计也只能说明数值合法，不能说明法线与真实表面相符。

## 4. 完整场景暴露出的导出规模问题

原始导出仍是500万目标样点和Poisson depth9，但场景和视角规模已经变化。[网格核验][validation]

| 项目 | 已测结果与含义 |
| --- | --- |
| 每训练视角样点 | 3,383；s01为25,907，本轮单视角采样密度只有原来的13.06% |
| 累积不透明度alpha=0的样点 | 120,332 / 5,000,074 = **2.4066%**；s01只有43点，当前确实混入了大量没有累积支持的样点 |
| 预测深度超0.3–6m的样点 | 820,197 / 5,000,074 = **16.4037%**；它们没有该监督范围的直接约束，但不能一律认定为错误 |
| 渲染Z范围 | 0.01361–18.44840 m；采样没有近距/远距支持筛选 |
| 名义depth9最细格尺度 | **0.077515 m，约7.75cm**，按 `1.1 * PCD最大轴跨度 / 512` 计算 |
| 反算PCD最大轴跨度 | 约36.07988m；这不是独立测量的真实大厅尺寸 |
| 最大连通分量 | 2,035,931 / 2,102,867面 = **96.8169%**；主体集中，但连续伪面同样可以形成大分量 |

7.75cm是八叉树上限深度对应的名义物理格尺度，不是实际误差，也不是“所有三角形边长”。同样的depth9在更大范围里不具有相同物理细节能力，薄板、椅腿等结构容易受到影响。仅调高depth也不能消除输入的无支持点和跨视角矛盾。

alpha=0样点值得处理：历史模型把这些像素的深度填成本帧最大预测Z，原始导出又以非零深度为候选，因此有限正深度并不代表存在可观测表面。它们可能干扰融合，但现有证据不足以断言2.4%的点独自导致所有网格伪面。[模型深度填充值][model]、[历史导出器][exporter]

## 5. 下一轮可直接执行的一套完整导出适配

以下为**建议协议，尚未执行或证明有效**。它是面向本采集的sensor-supported派生网格，需明确标记方法变化，不能写成原论文未改动的Poisson结果。它覆盖全部主训练视角和全程空间观测，但会放弃没有可靠近距支持的表面；不会自动补回整个大厅远景。

保留本次原始30k点云/网格作为baseline。在当前30k checkpoint及下一轮最终checkpoint上各运行一次完全相同的全场派生导出，可分别观察导出改动和模型改动的效果，不再做桌沿小样本参数扫点。

### 固定候选与采样

建议采样候选同时满足：预测深度/法线有限且法线非零；alpha≥0.5；预测Z在0.3–6m；同像素主训练传感器Z有效；`abs(predZ-sensorZ) <= max(0.05m, 0.03*sensorZ)`。这些阈值是预先固定的工程选择，不是从test调出的精度证书。逐帧记录每个条件剔除数、交集数和最终空间/时间覆盖。

只用主train传感器参考，辅助建图图像、val和test不参与筛选、融合或裁剪。法线仍从模型输出按既有坐标链变换；不得在导出中用真实深度替换预测深度，却继续把结果称为模型的几何。

每视角最多25,907点，恢复s01的每视角样点预算；1478视角最多38,290,546点。候选不足时全部保留并记录，不能重复抽样假装填满预算。用实际调用的0.01m体素融合控制冗余，融合后重新归一化有效法线并记录零/相消法线。

**历史DepthAndNormalMapsPoisson虽然声明了 `down_sample_voxel` 字段，实际main流程没有调用它。** 新版本需要真正执行分块/体素融合并记录前后点数，单独传入这个参数不会生效。[历史导出器][exporter]

### 固定曲面与支持裁剪

建议一次使用Poisson depth11，保留未做支持裁剪的派生网格。若范围仍与当前raw PCD相同，名义最细格约1.94cm；实际范围改变后重新计算。这仍不保证恢复厘米以下的薄结构。

为避免Poisson再次在无观测区域补出遮挡面，可在完整运行中追加仅依据train的可见自由空间/表面支持裁剪，保留裁剪前后两个产物。具体多视角支持和冲突规则需在正式导出前固定到协议，不能查看test后调整。建议记录三角形中心及顶点在各训练视角的有效参考、正支持 `abs(z-ref)<=tau` 和前方自由空间矛盾 `z<ref-tau` 计数；使用同一 `tau=max(0.05m,0.03*ref)`。例如采用至少两视角正支持并剔除两视角以上明确前方矛盾的保守规则，必须同步披露删除比例及由此留下的孔洞。

当前图中的近前方遮挡面应在这种支持核验中显露，但结果可能牺牲覆盖。评价时完整参考分母保持不变：同时报告命中覆盖和命中处误差，不能只在保留下来的小区域报一个更好MAE。

### 资源与完整交付

38.29M是采样上限而非要求全部同时常驻。逐视角/分块导出，先融合再Poisson；不要同时保留多份float64点云、全图缓存和完整大模型。依据实际可用120GB主存和任务峰值安排阶段，Poisson原生线程可使用已分配CPU，但GPU训练与高内存Poisson只有在峰值预算足够时才并行。资源记录与必要的等价分块处理属于正式流水线，不再新增smoke任务。

交付完整全局网格、固定三处局部、全部可评价留出视角的网格深度一致性/覆盖、共同支持指标、点来源和前方伪面统计。原始baseline、支持筛选后点云、Poisson未裁结果和最终裁后结果分别登记路径与SHA；只做这一套预固定适配，不提前保证几何改善。
