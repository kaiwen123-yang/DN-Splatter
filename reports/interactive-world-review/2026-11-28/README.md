### 已做过的工作不能再冒充创新

B3 已做独立时空组、多视角支持 S / 自由空间冲突 C、源组排除和留组核验，权重为 (1+S)/(1+S+C)。它针对已有有效深度使用 weighted edge-aware log-L1；无证据有效点仍为 1，空洞为 0。B3 还实现 SIFT、EPnP、联合重投影/极线优化与独立验证，但接受位姿改动为 0。额外纹理细分因证据/贡献高斯身份接口不足而没有启用。

因此“再做置信度加权”“再做局部 BA”“沿 RGB 边缘加点”都不够构成新贡献。必须落实新的候选来源、独立证据、学习目标、更新机制及可证伪对照。

## 4. LingBot-Depth：这轮测出了什么，哪些口径需补充

已经完成 1478 张无人工遮挡推理和 60 次固定人工遮挡推理。计分掩码和输入遮挡分开，连续块完整置零；模型和 NN 看同样的隐藏输入，未发现将计分深度回灌到模型的实现问题。

| 固定隐藏测试 | LingBot 10 cm 正确恢复覆盖 | 同输入二维 NN | LingBot 条件 MAE / NN |
| --- | ---: | ---: | ---: |
| 10% 散点 | 76.03% | 99.34% | 25.46 / 1.02 cm |
| 64×64 连续块 | 74.92% | 78.77% | 30.15 / 17.44 cm |

这些覆盖率都以全部计分像素为分母，无效预测是 miss。散点任务排除了边界，邻域读数仍密集，对 NN 有合理的结构优势，不代表 NN 会解决真实大孔洞。逐帧上散点 30/30 都是 NN 更好；块状有 8/30 帧 LingBot 的 10 cm 覆盖更好，说明可以研究条件选择，而非整图替换。

### 4.1 “99.45% 补满”不等于“99.45% 可用”

从 metrics.json 直接复算：

- 原全距离深度的无值孔洞：901,836,249 像素。
- 得到有限正预测：896,873,869，覆盖 99.4497%。
- 其中落在 0.3–6 m 以外：462,513,769，占已填预测的 **51.5695%**。
- 在当前评测区间内的正预测覆盖原孔洞：**48.1640%**。

区间外可以是真实远背景，不能一律判错；但也不能拿正数覆盖当作可用表面覆盖。下轮必须并列报告 finite-positive、范围有效、独立观测可验证、误差阈值内四种覆盖。

### 4.2 视频中的规则黑孔有明确的成像链原因

原深度画布为 848×480，配准输出为 1280×720。现有 capture_rectify + zbuffer 用单点前投影、四舍五入到一个像素、minimum.at 取最近 Z，没有按原测量足迹铺满目标画布。

即使原生 407,040 个深度像素全部有效且投影不重叠，单像素写入也最多覆盖 RGB 画布的 **44.17%**。实际全距离无值比例为 66.21%，所以这些空位不能全部解释为传感器未测到真实表面。它们混有重采样空隙、原生失效、视场/遮挡等因素；当前文件不能把所有来源唯一拆开。

这解释了为何必须增加 sensor-only footprint / 多视角量测融合对照，并保存 source pixel lineage。它**尚不能证明**栅格稀疏就是 LingBot 当前长尾失败的唯一原因。

### 4.3 1.88% 的双视角支持不是模型正确率

64 个诊断视角共有 39,277,863 个自然孔洞，其中 737,442 个有两邻视图传感器相符支持，即 1.8775%。在其中有有效预测的位置，85.04% 落在支持带内。

但评估每帧最多取两个邻视图，64 帧中只有 53 帧拿到两个邻视图；投影也是单像素栅格化，还依赖 B2 位姿。因此 98.12% 的缺证据位置不能算错误。扩大独立可见证据、修正可疑配对机制、保持遮挡为 unknown，都是必要的新实验。

### 4.4 重尾比平均偏移更值得优先处理

原有效区修改幅度中位 3.43 cm，均值 27.51 cm；模型对传感器边界区的改动 MAE 约 1.23 m，P95 约 5.64 m。它们是与传感器的分歧，边界传感器自身也可能错，不能直接当真值误差。但极大尾部与细结构应用不相容。

Depth 对照图能看到椅架形状被补出，泡沫齿边仍接近平滑。下轮要研究“何时采用哪一候选、何时不采用”，并用真实几何边界验证容量分配；不能只让全图变稠密。

## 6. 从灵波工作中最应该学什么

### Depth：把实测几何作为条件，学习缺失区域的结构

MDM 的 RGB 与深度分别嵌入，未缺失的深度与 RGB 联合参与空间推断。论文不是仅随机挖点：全失效 patch 必遮，部分失效 patch 高概率遮，再随机补足总体遮挡比例；还构造真实和合成 RGB-D 数据。它给本项目的启示是：按实际传感与配准链设计遮挡和监督，学习“有测量条件的补全”，而非仅用 RGB 猜深度。

下一轮可落地：原始测量足迹/块/边界三类隐藏协议、逐 mask 重算的冻结 LingBot 候选、使用 MDM 局部特征的 Q1 质量头，以及不使用该表征的 Q0 对照。不是把官方 mask 当错误概率。单帧模型论文中的平稳视频表现，不等于已经提供严格时间一致性约束。

### Map：世界模型需要记忆，也需要修订记忆

Map 的 anchor、局部 pose-reference window、trajectory memory 提供不同尺度的上下文。Map 2 进一步研究新信息到来后对空间上下文做 reconsolidation，然后继续流式推理。对本项目最重要的启示是：场景状态应能被后来的证据修订，而不是每次从零重建，也不是让第一次猜测永久固化。

实际公开 checkpoint 是 **pure causal base，没有 GCR**。自建显式对象证据记忆、局部回溯优化与数据版本更新是本项目新模块，不能称为已经复现了 GCR 网络。KV cache 也不自动等于对象身份、碰撞形状或物理状态。

本轮拟修改的是外部对象/几何证据状态，供后续融合、碰撞和数据生成读取；公开 Map base 的内部 KV 不会自动同步修订。这个接口边界必须写进实测报告。

### World 2 / VA：借鉴动作条件与长时一致性，保持本轮范围

LingBot-World 2 的持续交互和因果分块值得作为远期架构参照。但视频交互模型的动作、画面与显式米制碰撞标签不是同一接口。当前先把 Depth / Map 转成可验证几何、局部对象状态和真实动作回放；VLA / VA / World 大模型训练不进入本轮默认执行矩阵。

## 7. 计算与资产的真实限制

Map 稳定段输入处理 P50 29.1 ms，同步模型步骤约 32.8 ms；后者含 CPU dispatch，不是纯 GPU kernel。9.73 GiB 是 torch 张量分配峰值，不是整卡占用。Depth 的稳定 GPU 段约 55.1 ms，端到端约 96.2 ms。CPU 解码预取、落盘、评估和下一任务并行有明确空间，提升倍数需要实测。

视频编码已有新的实际解决记录：旧 FFmpeg/NVENC API 不匹配后，94d17e9 使用项目内 PyAV 15.1.0 成功生成 NVENC 成片。下一轮优先复用 scripts/lingbot_record_hall.py 及该局部环境，不再把旧编码问题当成未解决障碍，也不需要更换全局驱动。

历史 DN 训练峰 RSS 约 79 GiB。120 GB 主存下不能因为有 96 GB 显存就默认同时放六个完整训练进程。六条工作线应按 RSS、显存峰值和线程预算动态调度，实施只读共享缓存 / mmap 后再提高重训练并发。

更重要的是，上轮 execution.md 明写 **新实例数据盘为空后恢复**。恢复白名单包含 B2 相机/划分/RGB/Z/标定，不包含 B2/B3 checkpoint、DN 环境、VR/Faro 或原生 depth packet。历史完成回执不等于这些资产现在都在新服务器。下一轮应按已有清单恢复必要资产；读取既有归档允许，但不新增电脑归档，不删除服务器数据。

## 8. 下一轮应证明的三个研究假设

1. **几何假设**：灵波提供的候选在正确的传感器足迹输入和独立证据校准下，能在相同覆盖率上改善错误风险，并补回 sensor-only 方法无法恢复的结构。
2. **更新假设**：保留来源、可见性和对象版本的空间记忆，在新观测/动作后比不可撤销融合更少产生重影、错误删面和错误相机更新。
3. **任务假设**：上述几何和状态更新能改善留出动作的对象轨迹、接触与数据合格率；有帮助的数据还应在一个小型预测任务上表现出增益。

前两项的新颖性仍需与现有方法严格比较；第三项需要动态数据。只在大厅静态画面上提高 PSNR，不足以验证最终目标。完整实验矩阵、代码入口、资源调度和完成标准见下一轮计划。

为建立灵波与动作任务之间的直接证据链，计划额外采用已核实存在的 PhysTwin 三视角 RGB-D 推绳 case，在共同、仅由训练前缀形成的物理先验下，比较 NN、灵波直接补全、灵波证据筛选后的状态修订与 0.5 秒未来预测。公开 PushT 本身只有 RGB 与执行器 xy，不能借它直接证明灵波恢复碰撞几何。两条动态分支目前都只是已具备来源与协议的待执行实验。
