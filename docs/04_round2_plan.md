## 3. A：同一模型的结果诊断

### A1. 补充已有训练过程与恢复记录

从服务器已有日志和 TensorBoard event 提取必要的 loss、PSNR、步数/时间标量，保存小型 CSV/JSON 与曲线。附一份简短的失败/恢复记录，说明 PyTorch 2.7 checkpoint 的 NumPy scalar 加载错误及后续恢复位置；没有对应日志就如实写无法确定，不用时间空档猜测发生过什么。

首轮 `training` 阶段为 1,633.28 秒；它可能包含 `ns-train` 启动和 parser/先验准备。不能将训练后约 11 小时 48 分钟的空档算成训练时长，也不能未经拆分把它与论文 RTX4090 纯训练时间作硬件性能结论。

证据字段应表达真实检查范围：

- `runtime_validation`：正式 30,000 次更新、checkpoint 和评价已运行。
- `standalone_gradient_probe`：未运行；不为补字段另做无关测试。
- `normal_file_correspondence_checked`：逐帧文件名/尺寸核对；与法线空间方向核验分开。
- 网格基本结构检查：非空、有限顶点、合法三角形索引；不称为闭合、无自交或完整拓扑认证。

### A2. 完整留出帧与局部缺陷

固定已有 42 帧 `within` 和 186 帧 `with`，保存逐帧 PSNR/SSIM/LPIPS、深度误差和有效像素数。优先用原 checkpoint 的浮点预测和相同评价实现；不得从仓库缩略 JPEG 反算正式指标。若使用量化后的完整 PNG 做诊断，记录这种来源差异并与原始官方汇总分列。

两个轨迹分别按固定规则选最好、中位、最差视角及已有薄弱样例，给出参考 RGB、预测 RGB、误差图、深度和法线。逐帧指标用于解释视角覆盖、遮挡和细纹理误差，不在看完结果后删去较差帧。

对同一固定视角并排展示 **原始未裁剪 Poisson、官方裁剪网格和可用的 Faro GT**。使用相同相机、尺度、光照和色标，尤其检查当前两张裁剪网格预览中的粗糙表面、孔洞和碎边。区分导出本身的缺陷与可见性评价移除面片形成的边界，不能把所有空洞归因于训练。

### A3. 保留官方结果，另存明确定义的审计结果

**Faro 深度：**原 `faro_official_raw.json` 与第一轮 `faro_audited.json` 都保留。新增版本使用明确有效 mask，分别输出逐帧等权和全有效像素汇总的 MSE/RMSE、AbsRel、有效计数及标准 log-RMSE。mask 以参考深度有效且满足阈值为基础；预测非有限/非正值必须单独计数和报告，不能通过删除失败预测抬高指标。原 MSE 包含 GT=0 像素，原 `rmse_log` 公式也不是标准 log-RMSE，因此新旧字段不得混用或覆盖。

**法线：**对预测和 Omnidata 参考的真实编码先核对坐标约定，再从 `[0,1]` 解码至 `[-1,1]`，单位化后计算有效像素上的角度；报告朝向处理、有效 mask 和角度单位。输出名称为“与法线先验的一致性”，不能称 Faro 真值法线精度。保持训练法线和损失不变。

**可见性裁剪：**固定官方历史脚本接收 `test_ids` 却未用于过滤，当前 official 结果用全部 418 个 long_capture 注册视角。新增独立 `strict_train_only` 分支，只用已登记的 376 个训练视角对预测和 GT 都做同样裁剪；其余对齐、细分、遮挡阈值与距离阈值保持一致。分别保存视角清单及其哈希，输出 official 与 strict 两套结果。此差异属于评价口径，不等于训练用了留出图像。

如果要解释与论文仅 0.237 个百分点的 F-score 差值，优先对**同一已有网格**运行固定评价采样种子 `0,1,2`，保存全部数值、均值和范围。可以缓存同口径的裁剪结果，不必三次重复昂贵的裁剪，也不重新训练或反复导出以挑选最好网格。这只能估计评价抽样波动，不能代表训练随机种子波动，更不能提前断言原差值就是随机噪声。

新运行分别登记 `training_seed`、`mesh_sampling_seed`、`geometry_eval_seed`。第一次导出的未知种子保持 `unknown`，不能补写成 42。

## 5. C：自有数据入口

详细输入要求见 [自有数据说明](06_custom_data.md)。目前用户未提供本项目自有数据的目录、格式、内参或位姿，不自行认领其他项目数据，不猜服务器上的私有目录。

先建立独立配置/入口，保留 `dataset_path=null` 和 `waiting_for_dataset`。用户给出真实目录或样例后：

1. 只读盘点 RGB、深度、标定、位姿、时间戳和场景变化；能从文件确认的自行确认。
2. 静态 RGB-D + 可靠内参/相机位姿是首选入口；无位姿先补轨迹，RGB-only 另走 COLMAP/单目先验路径，不能假装已验证。
3. 在项目独立副本中统一单位、坐标、深度注册和命名；检查 5–10 帧反投影对齐后进入实际场景训练，不把检查扩展成反复短训练。
4. 每个新场景重新优化高斯。复用运行环境和先验网络，不从 VR Room 高斯 checkpoint 直接推理新房间。
5. 无 Faro/几何真值时明确未计算几何准确率；可交付留出图像指标、传感器深度一致性、渲染/网格及已知尺寸检查，不能伪造 F-score。

自有数据准备不要求先完成六个 MuSHRoom 场景。若真实数据已满足条件，可以在第二场景任务之后直接跑一个自有场景完整 30k；其数据特有设置单独记录，不冒称完全相同的论文基准。
